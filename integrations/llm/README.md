# LLM 插件

源码已实现 QQ 全文本响应、LLM 内存上下文和受限单群主动聊天，并已有定向测试覆盖。`plugins/ollama.js` 支持 Ollama 与 OpenAI 兼容的非流式 Chat Completions。本文是当前行为指南；授权部署、真实消息收发和云端构建仍需分别验证，不能由源码或定向测试结果代替。

## QQ 文本响应

QQ 文本不再要求 @机器人，响应顺序为“旧插件 → 真实语料匹配 → LLM”。插件已处理或语料真实命中时不额外调用 LLM 生成第二条回复；语料未命中再进入 LLM，原有“小夜”前缀仍显式可用。默认/所选人设作用于 LLM 请求，不会重写旧插件和已匹配的语料回复。`ChatProcess` 旧调用仍兼容随机兜底，新 QQ 路线不使用该随机兜底；`legacyReplyMode` 仅为 `StartQQBot` 内部注入的 options，未新增公开 config，不应写进 YAML。

## 会话上下文

上下文按平台、机器人 self 标识、会话类型及私聊用户或群分别隔离，每会话最多 40 条消息、有效期 2 小时。历史消息与当前 user 合计最多 16000 个 UTF-16 字符，不含 system 提示词，不是精确 token 预算；实际保留条数可能因字符裁剪而更少，40 条不等于 40 轮。请求使用所选人设与场景的 system、可用历史及当前 user。

上下文只存内存，重启清空，切换人设清空对应会话。人设/模型选择的持久化与聊天历史不同，不提供跨重启的长期记忆。

## QQ 图片对话

NapCat / OneBot 的私聊、群聊图片继续由现有 `ollama` 插件处理，不需要新插件、指令或 HTTP 入口。支持单独发图片及图片配文字，群内无需 @；仍遵守群服务和插件开关，不改变旧插件与群玩法的优先级。请求沿用当前会话的模型、人设及文字上下文，纯文本请求格式保持不变。

每条消息最多 3 张 JPG、PNG 或 WebP；单图下载上限 4MiB，合计 8MiB，解码上限 2000 万像素。识别前自动旋转、缩放至最长边 1024px，转换为不含原始 EXIF 的 JPEG。图片准备总截止时间为 5 秒，之后使用既有模型请求截止时间；图片请求建议将 `System.PLUGIN_TIMEOUTS.ollama` 设为 `timeoutMs + 6000`，例如 HTTP 30000ms 时使用 36000ms，其他插件不变。

识别仅接受 QQ 图片 CDN 的 HTTPS 地址，不访问用户任意网址、本地路径或重定向；只有不含路径的 OneBot 图片 ID 可以通过 `get_image` 解析，再验证 CDN 地址。图片以本次请求的内存数据发送给配置的模型服务，不保存到识别历史；后续历史只保留 `[图片]`、配文和机器人实际发出的文字回答，不重新上传旧图。原有图片转发/本地保存开关的行为不变，启用时仍按原逻辑保存。

无法下载、图片过大、损坏或格式不支持时返回明确提示，不调用模型猜图。带图请求被服务以 400/415/422 拒绝时提示当前模型或服务不支持图片识别，建议更换视觉模型或补充文字；这不等于已经确定某个模型没有视觉能力。超时不自动重试，也不自动换模型或退回随机语料；后续纯文字对话不受影响。模型列表不保证每个条目都支持视觉。

验收时在同一私聊或群中先说明一个话题，再发图片并配上问题；同时检查人设、文字追问、纯图片、多图和格式错误提示。真实 QQ 收发和手机显示需要独立验收，单元测试不能代替。

## 单群主动聊天

主动聊天仅面向已授权的单个测试群。公开示例群号为 `123456789`，不是实际目标或发送授权；实际目标保存在私密配置中，不扩展至其他群或私聊。runtime 只接受单个群目标，多群配置拒绝。

调度间隔 10–30 分钟，每日最多主动发送 12 条；按 `Asia/Shanghai` 在 23:00 至次日 08:00 严格静默，没有公开豁免或演示 HTTP 入口。无合适上下文时跳过，模型也可决定不发；跳过不补发、失败不重发。保持机器人身份，不模仿人类，不回复自身消息；stop 清理定时器并停止后续调度。

合并到现有 `llm` 节，保留其他字段；下方群号仅为公开示例，不是实际授权：

```yaml
llm:
  proactive:
    enabled: true
    groupIds: ['123456789']
    minDelayMs: 600000
    maxDelayMs: 1800000
    dailyLimit: 12
    maxIdleMs: 7200000
```

只有布尔值 `enabled: true` 启用，未配或其他值均不启用；`groupIds` 默认 `[]`，未配或为空时关闭并 fail-closed，不推导默认目标。启用时只接受单个群号，多群配置拒绝。`maxIdleMs` 为 2 小时，没有合适的近期上下文时仍跳过。

主动发送前查询 NapCat 机器人自身 `shut_up_timestamp` 与群 `group_all_shut`，并检查 LLM/proactive 两个插件开关；禁言、任一关闭、查询失败或状态未知均不发送。日额度只在当前进程内存保存，重启清空，不持久化、不跨进程共享；`dailyLimit: 12` 不提供跨重启或多个进程合计的硬配额。该 NapCat 保护与定向测试不等于真实收发或云端验收，不宣称 SnowLuma 已真实测试。

## 人设

默认使用内置的小夜原生人设，不会自动选用目录中的女友或其他人设。
可选文件位于 `plugins/persona/`，仅接受该目录直属的普通 `.txt` 文件，不接受路径或符号链接。

- `/更换人设` 或 `/更换人设 列表`：列出文件和序号，0 表示小夜原生。
- `/更换人设 查看`：查看当前会话的人设。
- `/更换人设 大肥鱼女友版.txt` 或 `/更换人设 1`：按文件名或当前列表序号切换。
- `/更换人设 重置` 或 `/更换人设 0`：恢复小夜原生。

每个私聊用户、群聊、平台和机器人身份分别隔离，群内选择对该群生效。
选择保存到本机 `config/llm-persona-state.json`，会话标识以哈希存储；文件被 Git 和发布包排除。
可通过 `llm.personaDir`、`llm.personaStateFile` 调整目录和状态文件，状态文件父目录需已存在。
同一状态文件只允许一个写入实例；正式程序、临时验收和插件测试器并行运行时，应分别指定不同状态文件。
选中文件被删除或失效时恢复原生；状态文件损坏则返回错误，不会静默覆盖。
单个人设最大 128KiB。人设与场景放在 system 消息，用户发言独立放在 user 消息，不记录正文日志。

## OpenAI 兼容服务

在 `config/config.yml` 中添加下列配置；不要覆盖已有 `System` 字段，应合并新增项。

```yaml
System:
  PLUGIN_TIMEOUTS:
    ollama: 31000

llm:
  provider: openai
  baseUrl: https://your-server.example/v1
  model: gpt-6-luna
  apiKeyFile: config/llm.credentials.json
  timeoutMs: 30000
  modelAdminQQs: ['10001'] # 替换为允许更换模型的 QQ 号
```

在本机私密文件 `config/llm.credentials.json` 填写 `{"apiKey":"你的密钥"}`，
或通过 `CHATDACS_LLM_API_KEY` 环境变量提供密钥，环境变量优先。不要把密钥写入主配置或聊天消息。
凭据文件被 Git 忽略，构建脚本也明确排除 `*.credentials.json`。

`baseUrl` 应指向 `/v1`，客户端追加 `/chat/completions`。远程服务必须使用 HTTPS；
本机回环地址允许 HTTP。带账号密码、查询参数或 fragment 的地址不接受，也不跟随重定向。
模型名原样传给服务，不会自动切换为其他模型或回退到旧 Ollama。

`timeoutMs` 为 HTTP 请求的总截止时间，范围 100–120000ms，超时取消请求。
`System.PLUGIN_TIMEOUTS.ollama` 按插件模块名单独覆盖软超时，设为 HTTP 截止时间加 1000ms；
其他插件仍沿用默认 8000ms。模块覆盖范围为 1–125000ms，非法值回退默认值。
请求失败不重试，鉴权失败、超时及空回复会产生明确的文本提示；日志不包含密钥、提示词和生成正文。

## 模型查询与切换

- `/查询模型`：查询服务模型列表第一页，每页 10 个；`/查询模型 2` 翻页。
- `/查询模型 luna` 或 `/查询模型 luna 2`：按关键词筛选并翻页。
- `/更换模型` 或 `/更换模型 查看`：查看当前会话模型和默认模型。
- `/更换模型 完整模型ID`：仅修改当前私聊或群聊；`/更换模型 重置` 恢复配置默认。

所有人可查询。修改和重置仅允许 `llm.modelAdminQQs` 指定的普通 QQ 账号，
适用于 QQ / NapCat 通道；未配置时不授权任何人修改，Web 等其他通道不会因数字 ID 相同而获得权限。
模型列表在服务端查询，缓存 60 秒并合并并发请求，OpenAI 兼容服务使用 `/models`，
Ollama 使用 `/api/tags`。查询不会调用模型生成，也不会自动探测或切换昂贵模型。
目录代表服务公布的模型，不代表已逐一验证调用额度和连通性；单次响应上限 2MiB，目录最多 5000 个 ID。

仅能选择服务列出的模型或配置默认模型。某些网关允许未列出的默认别名，
因此默认配置单独展示，不伪装成服务目录中的条目。远端列表失效或生成失败不会自动换模型。
选择保存到 `config/llm-model-state.json`；可通过 `llm.modelStateFile` 指定位置，
父目录需存在。状态文件被 Git 和发布包排除，平台/机器人/群或用户隔离规则与人设一致。
每个状态文件仍须单写入实例，临时验收与正式程序使用不同文件。

## 兼容旧 Ollama

未配置 `llm` 时，继续使用旧 `llamaUrl` 完整请求地址和 `model`；
均未配置时仍为原有 Ollama 地址和 `qwen2.5:3b`。旧问句降级回复保持不变。
此模式也受插件运行时软超时约束；需要更长时间时配置模块超时，而不是放大全部插件的默认值。

## 验收

1. 在授权测试会话中，不 @机器人、不加“小夜”前缀，发送一条确认未命中旧插件或本地语料的问题。核对语料未命中后确实调用 LLM，而不是随机兜底。
2. 在同一会话发第二条追问，检查是否带入相关历史；验证其他群或私聊不串上下文，隔离实例重启及切换人设会清空相应记录。
3. 用 mock 或隔离测试验证主动发送保护：双插件开关、禁言与未知状态、静默、无适合上下文、模型决定不发、多群拒绝、额度及 stop。不得为日常测试绕过静默规则。
4. 获准部署和发送后，分别核对模型结果、OneBot 回执和手机显示；未逐层确认前，不宣称手机已收到，也不将定向测试写作云端通过。
